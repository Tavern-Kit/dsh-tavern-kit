# Native MVU protocol sources

This directory implements native MVU parsing and JSON state updates. Card JavaScript is not executed.

- Primary source: [MagicalAstrogy/MagVarUpdate, d03b7dc8a6ebf9bd611c7e2dc91f3b35462deebc](https://github.com/MagicalAstrogy/MagVarUpdate/tree/d03b7dc8a6ebf9bd611c7e2dc91f3b35462deebc), MIT, Copyright (c) 2025 MagicalAstrogy & StageDog. The full notice is retained in [LICENSE-MagVarUpdate](LICENSE-MagVarUpdate).
- Native compatibility reference: dsh-Go revision `246f503a1f51720091cbef173150fdf3939a23d4`. Read and adapted the ordered initialization, metadata/schema inference, closed-markup extraction, seven commands, patch mapping, template merge, VWD/date updates and derived display behavior in [initialize.dart](https://github.com/ccch1mneyyy/dsh-Go/blob/246f503a1f51720091cbef173150fdf3939a23d4/packages/dsh_tavern/lib/src/mvu/initialize.dart), [schema.dart](https://github.com/ccch1mneyyy/dsh-Go/blob/246f503a1f51720091cbef173150fdf3939a23d4/packages/dsh_tavern/lib/src/mvu/schema.dart), [markup.dart](https://github.com/ccch1mneyyy/dsh-Go/blob/246f503a1f51720091cbef173150fdf3939a23d4/packages/dsh_tavern/lib/src/mvu/markup.dart), [update.dart](https://github.com/ccch1mneyyy/dsh-Go/blob/246f503a1f51720091cbef173150fdf3939a23d4/packages/dsh_tavern/lib/src/mvu/update.dart) and [values.dart](https://github.com/ccch1mneyyy/dsh-Go/blob/246f503a1f51720091cbef173150fdf3939a23d4/packages/dsh_tavern/lib/src/mvu/values.dart).
- Read-only variable macro behavior follows [message_variable_macros.dart](https://github.com/ccch1mneyyy/dsh-Go/blob/246f503a1f51720091cbef173150fdf3939a23d4/packages/dsh_tavern/lib/src/macros/message_variable_macros.dart): dot/numeric-bracket lookup, missing-value preservation, compact JSON and recursive dollar-metadata omission from block YAML. Formatting uses the installed YAML library; exact whitespace can differ from Dart's serializer.

Parsing uses installed `yaml` 2.9.1, `json5` 2.2.3, `jsonrepair` 3.15.0 and `acorn` 8.19.0. Their original package licenses remain with those dependencies. No parser source is copied here. Acorn parses the command and value syntax; evaluation visits only supported JSON data and real-number arithmetic nodes. It does not run arbitrary identifiers, property access, getters, spread, assignments, function bodies or JavaScript callbacks. No `eval`, `Function`, VM, browser event bridge or card script runtime is used.

The public state has five required JSON object fields, plus JSON-valued extensions. Import rejects non-JSON values instead of dropping them. A legacy initialized-book string list is normalized to an object. Unlike the historical primitive-root quirk, replacing `stat_data` with a non-object is reported as a command issue because it cannot satisfy this public state contract. Explicit JSON pointers address literal keys without prototype inheritance. Changes are made on a fresh validated copy; the supplied baseline is never mutated.

Closed update/patch blocks are processed in source order; incomplete blocks are not completed implicitly. Each closed update region has an independent Acorn lexer so a malformed command literal does not consume later independent blocks. Within a region, a failed call recovers at the next tokenized semicolon. An offset-preserving temporary lexical view masks only Acorn-rejected spans or invalid literal newlines to locate that boundary and keep string contents opaque; every accepted call is strictly parsed from the original source, so recovery cannot silently turn an invalid number such as `1e` into a value. A bare input is accepted only as a command document beginning with an MVU call (possibly preceded by comments), not as ordinary prose. Initialization applies greeting commands only inside complete blocks. Unknown patch operations and invalid commands are reported while unrelated valid commands remain usable. Array removal compares JSON values recursively: object key order is ignored, while array order and scalar types are preserved. Stored old variable snapshots are read directly; this module does not replay old chats, select candidates, persist state or make model requests. Those lifecycle decisions belong to the conversation engine.

The optional synchronous `MvuExpand` callback preserves the existing call signatures. Initialization expands each stripped book declaration and greeting initvar before data parsing, then expands greeting updates; an update expands the supplied text before markup/command parsing. The caller supplies its frozen character/player and variable read context and retains the original text. This module does not import the prompt assembler or choose a live context itself.

The tests in `mvu.test.ts` in the source repository execute the actual parsers and protocol without a model, network, storage mock or interpreter substitute. Passing these tests does not claim compatibility with every SillyTavern extension, arbitrary script, HTML/MVU UI, provider or live DSH deployment.
